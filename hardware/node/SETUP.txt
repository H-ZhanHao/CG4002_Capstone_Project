HIP AND WRIST: SEPARATE BLUETOOTH MONITORS

Hardware: the existing FireBeetle ESP32 boards (ESP32-WROOM-32D), each with its
MPU6050. Keep the installed DFRobot board package 0.2.1.

Sketches to open in separate Arduino IDE windows:
  hardware/hip/hip.ino       Bluetooth name: ExerciseHip
  hardware/wrist/wrist.ino   Bluetooth name: ExerciseWrist

Both sketches use the same ExerciseNode library in hardware/node. The old
node.ino gateway is replaced by these two sketches. No role edits are needed.
Shared MAC addresses, thresholds and settings remain in ExerciseConfig.h.

ONE-TIME ARDUINO LIBRARY REGISTRATION (WINDOWS)

Run hardware/register-library.ps1 in PowerShell. It links hardware/node into
the sketchbook's libraries/ExerciseNode folder. The default sketchbook location
is Documents/Arduino. For a different location, use the Sketchbook location
shown in Arduino IDE Preferences:
  .\hardware\register-library.ps1 -SketchbookPath 'C:\path\to\Arduino'

This is a directory junction, so edits to ExerciseConfig.h apply directly to
both sketches; there are no separate copies of the counting algorithms to sync.
The script refuses to replace any existing different library. Reopen the IDE
after registration. Keep this repository at the same path while using the link.

UPLOAD AND CONNECT

1. In each IDE window choose DFRobot -> FireBeetle ESP32 (the original board).
   Use Partition Scheme: Minimal SPIFFS (1.9MB APP with OTA/190KB SPIFFS).
2. Upload hip.ino to the hip's USB port, and wrist.ino to the wrist's USB port.
   Upload BOTH boards: this protocol is incompatible with the old gateway code.
3. Power both boards. Their USB monitors at 115200 baud should show their role,
   Wi-Fi STA MAC, ESP-NOW ready, Bluetooth name, and STANDBY.
4. Pair the laptop with ExerciseHip and ExerciseWrist. Windows may cache the
   old ExerciseNode name; remove the old pairing and pair again if necessary.
5. Select ExerciseHip's outgoing Bluetooth COM port in the hip IDE window and
   ExerciseWrist's outgoing Bluetooth COM port in the wrist IDE window.
   Open both Serial Monitors; select Newline. Use 115200 for USB diagnostics.
6. Both wearables can now use battery power. Each monitor shows only its own
   board's output. Calibration details and hip fall alerts are not forwarded.

COMMANDS (USB OR BLUETOOTH, ON EITHER BOARD)

ACTIVATE
  Request that the OTHER board stop rep counting. Only after its standby ACK
  does THIS board begin a new baseline/calibration session with zero reps.
  An already-active board keeps its session; use RESET to recalibrate it.
STANDBY (DEACTIVATE is an alias)
  Stop THIS board's rep counting and cancel a pending activation. Bluetooth,
  ESP-NOW command reception, and hip fall monitoring remain available.
RESET
  Forget THIS board's calibration for the selected exercise and counting mode,
  and clear its rep count. An active board restarts calibration; an inactive
  board stays inactive. Other profiles remain saved. Cancels pending activation.
EXERCISE:<name>
  Select PUSHUP, SITUP, SQUAT, LUNGE, LEG_RAISE or JUMPING_JACK on THIS board.
  Plurals, spaces and hyphens are accepted (e.g. EXERCISE:leg raises).
  A different selection restarts the baseline and zeros reps, retaining saved
  movement calibrations. Active stays active; standby stays standby. A pending
  activation is cancelled. Repeating the current selection only shows status.
EXERCISES
  List the six exercise names. Selection is manual and local to each board.
MODE:PAUSE / MODE:CONTINUOUS (PAUSE / CONTINUOUS also accepted)
  Accepted only on the ACTIVE board. Change its mode and send it to the OTHER
  board over ESP-NOW. Commands typed on an inactive board are rejected without
  changing mode, resetting calibration, or sending a mode packet. The standby
  board still accepts synchronized changes from the active board.
  An actual mode change restarts the session on each board and cancels pending
  activation. Active stays active; inactive stays inactive. Sending the same
  mode again retries synchronization without resetting calibration.
  Wait for "Mode synced" on the sending monitor. If confirmation times out,
  the local mode remains selected; check the peer and resend the command.
  PAUSE is the pause-based counting algorithm, not a standby command.
STATUS / HELP
  Show this board's activation/radio configuration or the command list.

Type ACTIVATE in the HIP monitor for hip exercises; type ACTIVATE in the WRIST
monitor for wrist exercises. The other board automatically enters standby.
Mode changes from the active node's monitor are shared. Every successful activation
starts a fresh baseline. Move into position and hold still for three seconds.
If this exercise/mode has a saved profile, counting starts at zero immediately
after that baseline. Otherwise perform two matching calibration reps first.

PER-EXERCISE CALIBRATION

Each board keeps six exercise profiles, each with separate PAUSE and CONTINUOUS
movement limits. Profiles are saved automatically only after successful movement
calibration. Switching exercise, switching mode, or handing activation to the
other board preserves them. Incomplete calibration attempts are not saved.
The hip defaults to SQUAT; the wrist defaults to JUMPING_JACK. Either board can
select any exercise. Selecting an exercise does not change mode or active board.
Choose the mode explicitly; jumping jacks will usually use MODE:CONTINUOUS.

Example, in the chosen board's monitor:
  EXERCISE:SQUATS
  ACTIVATE
  MODE:PAUSE
  [move into position, hold still, perform two matching calibration reps]
  EXERCISE:LUNGES
  [repeat baseline and movement calibration for lunges]
  EXERCISE:SQUATS
  [repeat baseline; saved squat limits load and counting starts at zero]

Profiles are local RAM only: reboot/power loss clears all profiles on that board.
They are not sent over ESP-NOW. Select the exercise separately when using the
other board; it learns its own calibration for its sensor placement. STATUS
shows whether the selected exercise/mode has a saved profile; every telemetry
line includes the exercise name.

Only movement thresholds, duration limits, and (for continuous mode) the learned
axis/direction are reused. Gravity baseline and gyro bias are measured afresh.
Use RESET after moving/rotating the sensor, changing wearer or deliberately
changing movement range/pace. Keep the same placement when reusing a profile.
All exercises start with the existing shared detector settings; their learned
limits come from your own reps. No new exercise-specific thresholds are claimed
to be physically tested, and selecting a name does not recognize exercise form.

MIRRORED LED FEEDBACK

After movement calibration completes or a saved profile loads, BOTH LEDs blink three times quickly to
signal readiness: 100 ms OFF then 100 ms ON, repeated three times (600 ms total).
The initial OFF interval separates the pattern from the active calibration LED.
Each subsequently counted rep flashes BOTH LEDs once for 200 ms. This
works in either direction: HIP counting can be watched on the wrist LED, and
WRIST counting can be watched on the hip LED. The peer stays in standby for
counting; its local rep count and mode are not changed by an LED event.

Earlier baseline/calibration progress indications stay local to the active
node. No extra command is needed for mirroring. Durations are shared in
NodeSession.h under LedTiming. LED pulses are timed without blocking delays.

Resetting an active session, changing mode, or entering standby clears the
feedback locally and sends/uses a peer clear event as appropriate. Activation
handover clears existing pulses and binds new LED events to the new session.
Same-mode retries do not reset feedback or calibration.

LED events are best effort, without ACKs or retries. Wireless delay means the
flashes are approximately synchronized, not simultaneous. Lost packets can
cause missed remote flashes or a missed clear; any received flash still ends
after its own 200/600 ms timer. Count validity never depends on LED delivery.
Duplicate/out-of-order events are ignored using the session and sequence.
After the standby board reboots, switch activation away and back to establish
a fresh LED session. Repeating ACTIVATE on an already-active board does not
perform a new handshake. Neither event traffic nor STATUS proves a live peer.

SIMPLE CONTROL LINK

ESP-NOW uses 24-byte DEACTIVATE/STANDBY_ACK, SET_MODE/MODE_ACK and LED_FEEDBACK
packets. LED_FEEDBACK carries clear, calibration-ready or rep-pulse events,
bound to an activation session and ordered with a sequence number. There are
no discovery broadcasts, periodic heartbeats, sensor streams, forwarded counts
or remote fall messages. USB/Bluetooth output remains at the original cadence.

Activation tries at most five requests, 500 ms apart, with a 2.5-second deadline.
No ACK means no activation: the requesting node stays inactive and reports
ACTIVATION FAILED. If every ACK was lost, both nodes may be in standby. Both
boards must therefore be powered for a new activation, even for hip exercises.
Do not treat "ESP-NOW configured and ready" as proof the peer is reachable.

The hip's request wins when both requests are pending together. Request numbers
and a per-boot random ID prevent delayed acknowledgements from starting old
sessions. Receiving a deactivation always stops counting before acknowledging;
a delayed duplicate can conservatively stop counting again, never start it.
Old gateway packets are rejected by the new packet size/version.

Mode synchronization also uses five attempts, 500 ms apart, and a 2.5-second
deadline. Duplicate mode requests are acknowledged without recalibration;
older requests from the same peer boot and stale acknowledgements are ignored.
Entering standby cancels pending mode retries. An active board ignores incoming
mode requests from its peer, including delayed requests from before a handover.
Wait for acknowledgement before changing modes again. There is no periodic
mode synchronization: after reboot, the board uses the configured default.
Resend the desired MODE command from the active node to sync both after either
board restarts. If neither is active, activate the desired node first.
Upload BOTH sketches for this protocol update (version 4); older versions
cannot exchange activation/mode/LED packets with the updated firmware.

After selection, counting continues locally even if the other board loses power
or ESP-NOW reception. STATUS does not claim a peer is currently online because
there is no heartbeat. Rebooting either board always puts that board in standby.
Closing a Bluetooth monitor does not itself stop rep counting; use STANDBY.

Bluetooth and ESP-NOW still share each ESP32's radio. Lower ESP-NOW traffic is
not a guarantee of reliable switching on this board package. No sleep overrides,
coexistence-priority tuning, extra Bluetooth writer task, or radio statistics
have been added. Test switching before attempting exercise calibration.

BENCH CHECK BEFORE WEARING

- Power both boards, open both Bluetooth monitors; confirm both say STANDBY.
- Send ACTIVATE to HIP. HIP should report active and begin BASELINE; WRIST should
  report standby. Then ACTIVATE WRIST and check that the roles reverse.
- Repeat several times with both Bluetooth connections open and power unchanged.
- Send RESET on the active board: it should restart baseline without a switch.
- Send a MODE command from the standby monitor: expect "Mode command rejected"
  and no changes to either board's mode or calibration.
- Send MODE:CONTINUOUS from the active monitor: both should show CONTINUOUS and the
  sender should report "Mode synced". The active node stays active and starts
  baseline again, then load that mode's profile or calibrate if none is saved.
  Switch activation and send MODE:PAUSE from the newly active
  node to check the reverse direction too.
- Repeat the same MODE command: it should confirm sync without recalibration.
- With the peer off, a MODE command on the active node should apply locally then report sync
  unconfirmed. Restore peer power and resend the command to synchronize.
- Send STANDBY on the active board: both should now be inactive.
- Turn the OTHER board off and request activation: expect an explicit failure,
  not counting. Restore its power and send ACTIVATE again.
- Once a board is active, removing the other board's power must not interrupt
  its own counting/output. A subsequent activation on the other requires an ACK.
- Hip fall detection/buzzer remains running while its rep counter is in standby.
- Complete movement calibration on HIP: both LEDs should blink three times quickly.
  Count several reps: each should cause a 200 ms pulse on both boards, while
  WRIST output remains STANDBY. Repeat with WRIST active, in both counting modes.
- Send RESET or change mode during counting: previous feedback should clear,
  followed by another shared ready flash when calibration completes or a saved
  profile loads after baseline.
- Calibrate SQUAT and LUNGE in PAUSE mode, switch back, and confirm each restores
  its own limits after baseline with zero reps. Repeat in CONTINUOUS mode.
- RESET SQUAT/PAUSE, then verify LUNGE/PAUSE and SQUAT/CONTINUOUS remain saved.
- Reboot one board and verify its profiles clear while the other keeps its own.
- Turn off the standby board after activation: the active board must keep
  counting and flashing locally. Restore it and switch activation away/back
  before checking remote LED feedback again.

BUILD / HOST VERIFICATION

Arduino CLI can use the library directly without registration:
  arduino-cli compile --fqbn DFRobot:esp32:esp32:PartitionScheme=min_spiffs --library hardware/node hardware/hip
  arduino-cli compile --fqbn DFRobot:esp32:esp32:PartitionScheme=min_spiffs --library hardware/node hardware/wrist

Transport-independent switching tests (no hardware):
  g++ -std=c++11 -Wall -Wextra -Werror -Ihardware/node hardware/tests/node_session_test.cpp hardware/node/NodeSession.cpp -o .build/node_session_test.exe
  .build/node_session_test.exe

Exercise profile and detector tests (synthetic sensor samples, no hardware):
  g++ -std=c++11 -Wall -Wextra -Werror -Ihardware/tests/stubs -Ihardware/node hardware/tests/exercise_profiles_test.cpp hardware/node/RepCounter.cpp hardware/node/ContinuousCounter.cpp -o .build/exercise_profiles_test.exe
  .build/exercise_profiles_test.exe

These checks do not establish Bluetooth/ESP-NOW reliability on physical boards.
No firmware is uploaded by the build or library-registration steps.
