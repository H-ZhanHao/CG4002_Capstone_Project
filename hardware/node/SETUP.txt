HIP AND WRIST: SEPARATE BLUETOOTH MONITORS

Hardware: the existing FireBeetle ESP32 boards (ESP32-WROOM-32D), each with its
MPU6050. Keep the installed DFRobot board package 0.2.1.

Sketches to open in separate Arduino IDE windows:
  hardware/hip/hip.ino       Bluetooth name: ExerciseHip
  hardware/wrist/wrist.ino   Bluetooth name: ExerciseWrist

Both sketches use the same ExerciseNode library in hardware/node. The old
node.ino gateway is replaced by these two sketches. No role edits are needed.
Shared MAC addresses, thresholds and settings remain in ExerciseConfig.h.

ONE-TIME ARDUINO LIBRARY REGISTRATION (WINDOWS)

Run hardware/register-library.ps1 in PowerShell. It links hardware/node into
the sketchbook's libraries/ExerciseNode folder. The default sketchbook location
is Documents/Arduino. For a different location, use the Sketchbook location
shown in Arduino IDE Preferences:
  .\hardware\register-library.ps1 -SketchbookPath 'C:\path\to\Arduino'

This is a directory junction, so edits to ExerciseConfig.h apply directly to
both sketches; there are no separate copies of the counting algorithms to sync.
The script refuses to replace any existing different library. Reopen the IDE
after registration. Keep this repository at the same path while using the link.

UPLOAD AND CONNECT

1. In each IDE window choose DFRobot -> FireBeetle ESP32 (the original board).
   Use Partition Scheme: Minimal SPIFFS (1.9MB APP with OTA/190KB SPIFFS).
2. Upload hip.ino to the hip's USB port, and wrist.ino to the wrist's USB port.
   Upload BOTH boards: this protocol is incompatible with the old gateway code.
3. Power both boards. Their USB monitors at 115200 baud should show their role,
   Wi-Fi STA MAC, ESP-NOW ready, Bluetooth name, and STANDBY.
4. Pair the laptop with ExerciseHip and ExerciseWrist. Windows may cache the
   old ExerciseNode name; remove the old pairing and pair again if necessary.
5. Select ExerciseHip's outgoing Bluetooth COM port in the hip IDE window and
   ExerciseWrist's outgoing Bluetooth COM port in the wrist IDE window.
   Open both Serial Monitors; select Newline. Use 115200 for USB diagnostics.
6. Both wearables can now use battery power. Each monitor shows only its own
   board's output. Calibration details and hip fall alerts are not forwarded.

COMMANDS (USB OR BLUETOOTH, ON EITHER BOARD)

ACTIVATE
  Request that the OTHER board stop rep counting. Only after its standby ACK
  does THIS board begin a new baseline/calibration session with zero reps.
  An already-active board keeps its session; use RESET to recalibrate it.
STANDBY (DEACTIVATE is an alias)
  Stop THIS board's rep counting and cancel a pending activation. Bluetooth,
  ESP-NOW command reception, and hip fall monitoring remain available.
RESET
  Clear THIS board's exercise session. An active board restarts calibration;
  an inactive board stays inactive. Cancels any pending activation.
MODE:PAUSE / MODE:CONTINUOUS (PAUSE / CONTINUOUS also accepted)
  Change THIS board's counting mode and reset its calibration. Active stays
  active; inactive stays inactive. Cancels any pending activation.
  PAUSE is the pause-based counting algorithm, not a standby command.
STATUS / HELP
  Show this board's activation/radio configuration or the command list.

Type ACTIVATE in the HIP monitor for hip exercises; type ACTIVATE in the WRIST
monitor for wrist exercises. The other board automatically enters standby.
Each node retains its own selected counting mode. Every successful activation
starts fresh calibration. Move into position, hold still for three seconds,
then perform the existing movement calibration. Counts start at zero afterward.

SIMPLE CONTROL LINK

ESP-NOW carries only 20-byte DEACTIVATE requests and STANDBY_ACK replies. There
are no discovery broadcasts, periodic heartbeats, telemetry packets, or remote
fall/calibration messages. USB/Bluetooth output remains at the original cadence.

Activation tries at most five requests, 500 ms apart, with a 2.5-second deadline.
No ACK means no activation: the requesting node stays inactive and reports
ACTIVATION FAILED. If every ACK was lost, both nodes may be in standby. Both
boards must therefore be powered for a new activation, even for hip exercises.
Do not treat "ESP-NOW configured and ready" as proof the peer is reachable.

The hip's request wins when both requests are pending together. Request numbers
and a per-boot random ID prevent delayed acknowledgements from starting old
sessions. Receiving a deactivation always stops counting before acknowledging;
a delayed duplicate can conservatively stop counting again, never start it.
Old gateway packets are rejected by the new packet size/version.

After selection, counting continues locally even if the other board loses power
or ESP-NOW reception. STATUS does not claim a peer is currently online because
there is no heartbeat. Rebooting either board always puts that board in standby.
Closing a Bluetooth monitor does not itself stop rep counting; use STANDBY.

Bluetooth and ESP-NOW still share each ESP32's radio. Lower ESP-NOW traffic is
not a guarantee of reliable switching on this board package. No sleep overrides,
coexistence-priority tuning, extra Bluetooth writer task, or radio statistics
have been added. Test switching before attempting exercise calibration.

BENCH CHECK BEFORE WEARING

- Power both boards, open both Bluetooth monitors; confirm both say STANDBY.
- Send ACTIVATE to HIP. HIP should report active and begin BASELINE; WRIST should
  report standby. Then ACTIVATE WRIST and check that the roles reverse.
- Repeat several times with both Bluetooth connections open and power unchanged.
- Send RESET on the active board: it should restart baseline without a switch.
- Send STANDBY on the active board: both should now be inactive.
- Turn the OTHER board off and request activation: expect an explicit failure,
  not counting. Restore its power and send ACTIVATE again.
- Once a board is active, removing the other board's power must not interrupt
  its own counting/output. A subsequent activation on the other requires an ACK.
- Hip fall detection/buzzer remains running while its rep counter is in standby.

BUILD / HOST VERIFICATION

Arduino CLI can use the library directly without registration:
  arduino-cli compile --fqbn DFRobot:esp32:esp32:PartitionScheme=min_spiffs --library hardware/node hardware/hip
  arduino-cli compile --fqbn DFRobot:esp32:esp32:PartitionScheme=min_spiffs --library hardware/node hardware/wrist

Transport-independent switching tests (no hardware):
  g++ -std=c++11 -Wall -Wextra -Werror -Ihardware/node hardware/tests/node_session_test.cpp hardware/node/NodeSession.cpp -o .build/node_session_test.exe
  .build/node_session_test.exe

These checks do not establish Bluetooth/ESP-NOW reliability on physical boards.
No firmware is uploaded by the build or library-registration steps.
